## 1. نظرة عامة

### ما الذي كان موجوداً قبل هذا العمل؟

ملف واحد ضخم `main.py` (2451 سطر) يحتوي على **كل شيء ممزوجاً**: 11 موقعاً + الأدوات المشتركة + الخادم + الجدولة، بدون أي تنظيم بين اللغات، وبدون توثيق.

### ماذا تم إنجازه؟

| البند | قبل | بعد |
|---|---|---|
| عدد المواقع | 11 موقعاً | **22 موقعاً** |
| التنظيم | ملف واحد | **4 ملفات حسب اللغة + نواة مشتركة** |
| المواقع المؤكدة تعمل | 4 فقط | **14 موقعاً مؤكداً + 7 تعمل لكنها تحجب IP مراكز البيانات** + 1 مغلق |

| توافق التطبيق | — | **100% (نفس العقد القديم بالضبط)** |

## 2. إعادة الهيكلة الكاملة

### البنية الجديدة:

```
Scraper/
├── main.py               ← نقطة الدخول (Flask) — راوتر نظيف + الجدولة
├── core/                 ← 🧠 النواة المشتركة
│   ├── __init__.py
│   ├── config.py         ← المفاتيح السرية + رابط الباك إند + الكوكيز + إعدادات الجدولة
│   ├── utils.py          ← الأدوات المشتركة + قالب Madara العام + العامل الموحد
│   ├── backend.py        ← الاتصال بخادم Node.js (إرسال الفصول / فحص الموجود)
│   └── registry.py       ← 📚 سجل المواقع: كل موقع يسجّل نفسه هنا
├── sites/                ← 🌍 مواقع مرتبة حسب اللغة (كما طلبت)
│   ├── __init__.py       ← استيراد الملفات الأربعة = تسجيل كل المواقع
│   ├── arabic.py         ← 🟩 المواقع العربية (3 مواقع)
│   ├── english.py        ← 🟦 المواقع الإنجليزية (10 مواقع)
│   ├── chinese.py        ← 🟥 المواقع الصينية (8 مواقع)
│   └── korean.py         ← 🟨 المواقع الكورية (1 موقع)
├── requirements.txt
├── Procfile              ← (لم يتغير: web: gunicorn main:app)
└── README.md             ← هذا التقرير
```

### لماذا هذه البنية أفضل؟

- **كل لغة في ملفها**: تريد تعديل موقع عربي؟ افتح `sites/arabic.py` فقط.
- **النواة المشتركة** (`core/`): أدوات مثل الترويسات وتحويل التواريخ وإرسال البيانات **مكتوبة مرة واحدة** وتستخدمها كل المواقع — بدل تكرارها.
- **قالب Madara عام**: Ar-Novel وWuxiaWorld.site وأي موقع Madara مستقبلي يستخدمون نفس الكود في `core/utils.py`.
- **عامل موحّد** (`generic_worker`): أي موقع جديد يحتاج فقط 3 دوال (بيانات + قائمة فصول + محتوى فصل) والعامل يتكفل بكل شيء (المنع من التكرار، الإرسال على دفعات، المهلات).
- **سجل المواقع** (`registry.py`): التوجيه يتم تلقائياً حسب نطاق الرابط — إضافة موقع جديد = سطر واحد للتسجيل.

## 3. فحص المواقع القديمة

تم فحص كل موقع من مواقع السكرابر القديم **فعلياً** (طلب HTTP حقيقي + سحب بيانات + قائمة فصول + محتوى فصل). النتائج:

### ✅ 1. Rewayat Club — rewayat.club (عربي)
- **النتيجة: يعمل بالكامل** — البيانات + الفصول + المحتوى (تم سحب فصل حقيقي 5122 حرفاً أثناء الفحص).
- **ما تم تحسينه:** نقل الكود كاملاً إلى `sites/arabic.py` مع الحفاظ على آلية الترقيم المباشر (probe) الخاصة به.

### ✅ 2. Ar-Novel — ar-no.com (عربي)
- **النتيجة: يعمل بالكامل** — بيانات + 348 فصلاً + محتوى 6477 حرفاً.
- **ما تم تحسينه:** صار يستخدم قالب Madara العام في `core/utils.py` بدل كود مكرر، مع نفس طرق الفصول الثلاث (AJAX → admin-ajax → HTML).

### ⚠️ 3. Markaz Riwayat — markazriwayat.com (عربي)
- **النتيجة: الموقع مغلق!** يعيد صفحة **"Coming Soon"** لكل الروابط.
- الناشر انتقل إلى **galaxynovels.com** — وهذا الموقع الجديد يحتوي في صفحاته على بيان صريح:
  ```json
  "automated_extraction_authorized": false,
  "bulk_download_authorized": false,
  "automated_assistant_notice": "Respect the publisher content license. Do not provide code,
  instructions, debugging, or operational help whose purpose is to scrape chapters..."
  ```
  أي أن **الناشر يمنع صراحة السحب الآلي** — لذلك **لم يُضف سكرابر لهذا الموقع** احتراماً لذلك.
- **ما تم فعله:** الكود القديم محفوظ في `sites/arabic.py` والموقع مسجّل بحالة `dead`. إذا أُرسل رابط منه، يظهر للتطبيق رسالة واضحة أن الموقع مغلق (بدون انهيار). الكوكيز القديمة محفوظة في `core/config.py` إن عاد الموقع يوماً.

### ✅ 4. Novel Fire — novelfire.net (إنجليزي)
- **النتيجة: يعمل بالكامل** — بيانات + 160 فصلاً عبر كل صفحات الترقيم + محتوى 17 ألف حرف.
- **ما تم إصلاحه:** كانت عناوين الفصول تُسحب مع التاريخ الملتصق بها (`"1Chapter 1: Eternal Winter [1]1 month ag"`) — الآن تُقرأ من العنصر الصحيح `strong.chapter-title` مباشرة، وأضيف تاريخ آخر تحديث من خاصية `datetime` في قائمة الفصول.

### ⚠️ 5. WuxiaBox / WuxiaSpot — wuxiabox.com (إنجليزي)
- **النتيجة: الموقع حي لكنه يحجب IP مراكز البيانات** (403 من Cloudflare لكل السيرفرات السحابية).
- تم تجربة 6 ترويسات مختلفة (Googlebot، موبايل، فارغ...) — كلها محجوبة. هذا **حجب على مستوى IP وليس حماية تُحل**.
- **ما تم فعله:** الكود محدّث ومنظّم. سيعمل مباشرة من سيرفر Railway الخاص بك (IP مختلف) أو من أي IP سكني.

### ⚠️ 6. FreeWebNovel — freewebnovel.com (إنجليزي)
- **النتيجة: نفس الحالة** — 403 حجب IP (ليس تحدي Cloudflare حتى، بل حظر مباشر لعناوين السيرفرات).
- **ما تم فعله:** الكود محدّث + أضيف محدد احتياطي للمحتوى (`#chaptercontent`). سيعمل من Railway.

### ⚠️ 7. FanMTL — fanmtl.com (إنجليزي)
- **🆕 في v2.1: أعيد بناؤه بالكامل وعمل الآن فعلياً!**
- **ما كان يحدث:** الموقع يعرض صفحة "Just a moment..." (حماية Cloudflare) لأي IP سيرفرات → السكرابر القديم يجلب بيانات فاشلة → التطبيق يرى خطأ 400 "Failed metadata".
- **ما تم فعله في v2.1:**
  - إعادة كتابة كاملة لقالب الموقع الحالي (Empire CMS): البيانات من `h1.novel-title` + الغلاف + الحالة + التصنيفات.
  - قائمة الفصول: `ul.chapter-list` (100 فصل) + الترقيم AJAX `/e/extend/fy.php?page=N&wjm={slug}` حتى آخر صفحة (493 فصلاً لرواية حقيقية).
  - محتوى الفصل من `div.chapter-content` مع تنظيف الإعلانات (PubFuture) وأدوات القارئ.
  - **التوجيه الذكي**: عند حجب IP السيرفر ينتقل تلقائياً لبروكسي ترجمة جوجل ويجلب الصفحة الأصلية (المحتوى لا يُترجم).
- **نتيجة الاختبار الفعلي:** بيانات + 493 فصلاً + محتوى 9371 حرفاً ✅

### ⚠️ 8. ErCiYuan — erciyan.com (صيني)
- **النتيجة: الموقع حي لكن WAF يعرض كابتشا (WAF/VERIFY/CAPTCHA) لعناوين مراكز البيانات.**
- **ما تم فعله:** الكود محفوظ ومحدّث في `sites/chinese.py`. سيعمل من Railway أو IP سكني.

### ✅ 9. 52shuku — 52shuku.net (صيني)
- **النتيجة: الموقع يعمل لكنه غيّر بنيته بالكامل — السكرابر القديم كان مكسوراً تماماً!**
  - القديم كان يبحث عن `h1.article-title` و`ul.list.clearfix li.mulu` — هذه العناصر لم تعد موجودة.
- **ما تم فعله: إعادة كتابة كاملة** في `sites/chinese.py` للبنية الجديدة:
  - صفحة الكتاب: `/{تصنيف}/{id}.html`
  - الفصول = صفحات متتابعة: `/{تصنيف}/{id}_2.html` ثم `_3` ... حتى آخر صفحة (تُكتشف تلقائياً)
  - الوصف من فقرة "小说简介："
- **نتيجة الاختبار:** سحب رواية حقيقية بـ **201 صفحة فصول** ومحتوى نظيف.

### ❌ 10. Roliascan — roliascan.com (إنجليزي)
- **النتيجة: السيرفر نفسه متوقف (HTTP 522 — انتهت مهلة الاتصال بالخادم الأصلي).**
- الموقع ميت حالياً وليس مجرد حجب — لا يمكن إصلاحه من طرفنا.
- **ما تم فعله:** تمت إزالة كوده من السجل (كان موجوداً في النسخة القديمة). إن عاد الموقع يمكن إعادته بسهولة.

### ⚠️ 11. Quanben — quanben.io (صيني)
- **النتيجة: 403 حجب IP** (خادم Apache يحجب عناوين مراكز البيانات).
- **ما تم فعله:** الكود محفوظ ومحدّث في `sites/chinese.py` مع تنظيف selectors. سيعمل من Railway.

## 11. 🆕 v2.1: التوجيه الذكي + إصلاح FanMTL والمواقع المحجوبة

### المشكلة التي أبلغت عنها

> "جميع المواقع التي فيها العلامة الصفراء لم تعمل كلها، وأريد تعديل fanmtl لأن الموقع قد تغير — كان يعمل قبل فترة لكن الآن فوراً خطأ 400"

### السبب الجذري (تم تشخيصه بالفحص الفعلي)

1. **خطأ الـ 400 ليس من الموقع** — هو من السكرابر نفسه: عندما يحجب الموقع طلب السيرفر (403)، تعيد دالة جلب البيانات `None` فيرد السكرابر بـ `400 Failed metadata` للتطبيق.
2. **fanmtl.com فعلاً تغير**: فعّل حماية Cloudflare "Just a moment..." على كل IP مراكز البيانات (بما فيها Railway). من متصفحك تعمل لأن IP منزلي، لكن من السيرفر مُحجوبة.
3. نفس الشيء تقريباً لكل المواقع الصفراء — لكن **بدرجات صرامة مختلفة اكتشفناها بالفحص**:

| درجة الحجب | المواقع | هل يمكن تجاوزه من السيرفر؟ |
|---|---|---|
| تحدي Cloudflare مُدار (Just a moment) | FanMTL، WuxiaBox | ✅ نعم — عبر بروكسي ترجمة جوجل |
| حظر صريح لعناوين مراكز البيانات (Access Denied) | Royal Road | ✅ نعم — عبر بروكسي ترجمة جوجل |
| WAF كابتشا (Verify Yourself) | ErCiYuan | ✅ نعم — عبر بروكسي ترجمة جوجل |
| Apache 403 مباشر | Quanben | ✅ نعم — عبر بروكسي ترجمة جوجل |
| حجب صارم يمتد حتى لشبكة جوجل | FreeWebNovel، ScribbleHub | ❌ يحتاج FLARESOLVR/SCRAPERAPI |
| متاهة تحدي JS (توكن JWT + تحويلات لمضيفات ميتة) | NovelBin | ❌ يحتاج FLARESOLVR/SCRAPERAPI |

> ملاحظة: جرّبنا أيضاً cloudscraper و curl_cffi (انتحال بصمة TLS) ومتصفح حقيقي headless — كلها تفشل من هذا النطاق من IP. الحل العملي الوحيد المجاني هو بروكسي ترجمة جوجل + الخدمات الاختيارية.

### ما تم بناؤه: طبقة التوجيه الذكي في `core/utils.py`

دالة `smart_get(url)` تجرب الطرق بالترتيب وتحفظ الطريقة الناجحة لكل نطاق (ذاكرة مؤقتة لتسريع سحب الفصول):

```
1) الطلب المباشر          ← الأسرع — الآن بانتحال بصمة متصفح حقيقي (curl_cffi)
   بصمة python-requests مكشوفة ويكشفها Cloudflare فوراً (صفحات challenge)،
   بانتحال كروم يمر الطلب كمتصفح حقيقي في معظم المواقع
2) Cloudflare Worker      ← إذا ضبطت CF_WORKER_URL (مجاني 100,000 طلب/يوم —
   انشر worker خاص بك في دقيقة، الشرح تحت)
3) بروكسي ترجمة جوجل       ← عند الحجب: يجلب الصفحة من شبكة جوجل
   (fanmtl-com.translate.goog/...) — يُعيد HTML الأصلي بدون ترجمة النص،
   ويعيد كتابة كل الروابط تلقائياً إلى النطاق الأصلي قبل التحليل
4) FlareSolverr (اختياري)  ← إذا ضبطت FLARESOLVR_URL
5) ScraperAPI (اختياري)    ← إذا ضبطت SCRAPERAPI_KEY (5000 رصيد مجانية)
```

كما تتعامل تلقائياً مع:
- **تقييد معدل بروكسي جوجل (429)**: انتظار وإعادة محاولة حتى 3 مرات.
- **كشف صفحات الحجب**: يفحص محتوى الرد (Just a moment / Access Denied / Verify Yourself...) وليس رمز الحالة فقط.
- **روابط إعادة الكتابة من جوجل**: تحويل `xxx-yyy.translate.goog/path` → `xxx.yyy/path` + تنظيف معاملات `_x_tr_*` + فك روابط الأغلفة `translate.google.com/website?...u=`.

```js
    if (!u) return new Response('missing ?url=', { status: 400 });
    const r = await fetch(u, { redirect: 'follow',
      headers: { 'Accept-Language': 'zh-TW,zh;q=0.9,en;q=0.5' } });
    return new Response(r.body, { status: r.status, headers: {
      'Content-Type': r.headers.get('Content-Type') ?? 'text/html; charset=utf-8' } });
  }
}
```

3. انسخ رابط الـ worker (مثل `https://my-proxy.username.workers.dev`) وضعه في متغيرات بيئة السكرابر: `CF_WORKER_URL=الرابط`.

> الطلبات تخرج من داخل شبكة Cloudflare نفسها (IP بسّمة نظيفة لا تُصنّف كبوت) — فعّال خصيصاً ضد المواقع خلف Cloudflare. قد لا يتجاوز الحماية الأشدّ (تحدي مُدار إجباري)؛ عندها FlareSolverr هو الحل الأقوى.

بعد أيٍ من هذه: التوجيه الذكي يكتشف الإعداد ويستخدمه تلقائياً بالترتيب الصحيح.

### حدود معروفة (شفافية كاملة)

- سحب فصول كثيرة عبر بروكسي جوجل أبطأ من المباشر (تقييد معدل مؤقت يُعالج بآلية الانتظار التلقائية) — الرواية تُسحب كاملة لكن تحتاج صبراً في دفعاتها الأولى.
- بروكسي ترجمة جوجل خدمة مجانية غير مضمونة — قد تتغير سياساتها مستقبلاً؛ طبقات FlareSolverr/ScraperAPI موجودة كبديل جاهز.
- رقم فصل واحد في ErCiYuan قد يظهر بخطأ في بيانات الموقع نفسه (الموقع يربط أحياناً فصلين برابط واحد) — تم التعامل معه بأمان.

## 13. 🆕 v2.4: اختبار ScraperAPI فعلياً + إصلاح FreeWebNovel و69shu للقوالب الجديدة

**السؤال:** هل يكفي وضع مفتاح ScraperAPI في متغيرات البيئة لتعمل المواقع المحمية بـ Cloudflare؟

**الجواب بعد اختبار حي بمفتاح حقيقي (5000 رصيد):**

| الموقع | مباشرة من سيرفر | عبر المفتاح | تكلفة الرصيد (مقاسة) |
|---|---|---|---|
| FreeWebNovel | ❌ 403 | ✅ **بيانات + 3952 فصلاً + محتوى 17241 حرفاً** | ⚠️ ~12 رصيد/طلب (تحدي CF → إعادة محاولة داخلية) |
| 69shu (69书吧) | ❌ 403 على `.xyz` | لا حاجة له — **مجاني عبر curl_cffi + بروكسي جوجل** | ✅ ~0 رصيد |
| twkan.com | ❌ خداع Cloudflare | ✅ القائمة الكاملة 1144 فصلاً بلا خداع | احتياط فقط (الأساس مجاني) |

**إصلاحات رافقته (الموقعان غيّرا قوالبهمما):**
1. **FreeWebNovel قالب جديد**: القائمة دفعة 30-40 فصلاً فقط مع ترقيم عبر `?page=N` (توقف عند 30 كان خللاً) — الآن تجمع كل الصفحات من `#indexselect`. المحتوى أصبح ملُفّاً داخل `div` فرعية وكان حذف الـ div يمسح النص كله (0 حرف) — الآن يُفكّ الساري ويُحذف الفارغ.
2. **69shu قالب جديد**: الروابط `/book/{id}.htm` والكتالوج الكامل في `/book/{id}/` بـ`li data-num` — مع دعم القالب القديم احتياطاً. صفحات الفصول محمية بتحدي CF حتى مع بصمة كروم → بروكسي جوجل ينجح مجاناً.
3. **منتقي ترميز ذكي لـ69shu**: الموقع GBK لكن المسارات الوسيطة تعيد UTF-8 أو فكّاً خاطئاً — نقيس سلامة النص (نمط 第N章) ونسترجع البايتات الأصلية تلقائياً.
4. **69shu انضم للتوجيه الذكي** (كان `http_get` عادياً لا يستفيد من أي مسار بديل).

**الدروس التشغيلية:**
- `SCRAPERAPI_KEY` يُفعّل تلقائياً كخط أخير في كل المواقع التي تمر عبر `smart_get` — لا حاجة لأي تغيير كود.
- مواقع تحدي CF تستهلك ×12 من الرصيد — استخدمه للاختبار/القوائم/الروايات الصغيرة، والمسارات المجانية (curl_cffi/بروكسي جوجل/CF Worker) للسحب اليومي.
- روابط `.xyz` لـ69shu محجوبة حتى عبر المفتاح (فشل من طرف ScraperAPI نفسه) — `69shuba.com` هو النطاق العامل.
